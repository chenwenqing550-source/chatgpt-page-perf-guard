# v1.7 Performance + Handoff Design

## Goal

把扩展从“固定频率监控 + 一刀切长聊天渲染优化”升级为“被动精确采集 + 页面繁忙时主动让路 + 远屏历史冷却 + 短期本机诊断 + 安全换窗交接”。目标不是让压力数字更漂亮，而是减少扩展自身主线程开销、提高瞬时卡顿定位精度，并在长会话继续恶化时提供高保真换窗路径。

## Root-cause hypothesis to validate

用户已观察到：卡顿会在生成回复过程中出现，并且刷新页面后恢复。当前实现同时存在周期 rAF burst、周期 coverage `getBoundingClientRect()` 扫描、页面压力更新，以及全消息 `content-visibility` 优化。v1.7 不把任何单一因素直接宣判为根因；先通过自耗时、busy/scroll/generating 状态和短期事件环形缓冲建立时间相关证据，再决定是页面原生渲染、扩展采集、布局优化或它们的叠加。

## Architecture

1. `monitor.js` 增加轻量运行状态机：`quiet / generating / scrolling / busy / background`。页面越忙，扩展主动工作越少。
2. 优先使用 `PerformanceObserver` 的 LoAF/LongTask 和 Event Timing；rAF burst 降为缺失被动信号时的低频 fallback，并在 scrolling/generating/busy/background 时停用。
3. 用 MutationObserver 做增量 DOM/生成活动计数，用 IntersectionObserver/有限近视口状态替代周期最多 120 节点的 `getBoundingClientRect()` 扫描；禁止滚动中批量布局读取。
4. `content-visibility` 只应用于远离视口、稳定的历史 turn；当前/最近/正在增长的消息不进入冷却。采用预热/冷却滞回，避免接近视口时才突然真实布局。
5. 维护 60~120 秒仅内存诊断 ring buffer：时间、LoAF/LongTask、event latency、drift、mutation rate、scroll/generating/busy、loaded blocks、优化状态、扩展主动工作耗时。不得保存聊天正文，不上传，不持久化。
6. Popup 展示“当前运行状态 / 插件是否让路 / 最近卡顿事件 / 插件自耗时”，并保持 page pressure 与模型上下文使用严格分离。
7. 内置“换窗交接”：默认智能模式只准备结构化压缩指令到 ChatGPT 输入区，由用户手动发送；不自动创建新聊天、不自动发送。交接保护字段至少包括目标、当前阶段、已确认决定、硬约束、repo/branch/SHA/version、已完成 Evidence、PENDING/BLOCKED、废弃历史、当前问题、下一步、Stop Rule。
8. DOM 全文自动抽取不作为默认正式路径；本地模式只接受用户显式提供/选择/导入的数据。任何未来实验性 DOM 抽取必须默认关闭并独立标注。

## Lifecycle / load shedding

- `quiet`: 完整被动监控，允许必要的低频 fallback 校准。
- `generating`: Mutation 速率高或最后消息持续增长；暂停 coverage/layout 类工作与 rAF burst。
- `scrolling`: wheel/touch/pointer/scroll 活跃；暂停所有主动布局读取，保持被动 observer。
- `busy`: generating + scrolling 或近期 LoAF/高 drift；进入最低干扰模式。
- `background`: 非必要采集全部休眠，仅保留恢复所需最小状态。
- 状态稳定 2~3 秒后再恢复一次校准；禁止繁忙态结束瞬间集中补做大量工作。

## Performance acceptance

1. 生成回复并快速滚动时，扩展不执行批量 `getBoundingClientRect()` coverage 扫描。
2. 页面繁忙时 rAF fallback 不运行；被动信号可用时默认不依赖持续 rAF 采样。
3. 扩展自身主动测量耗时可观察，并能与卡顿事件时间关联。
4. 后台标签页不持续进行非必要采样。
5. 长聊天优化不能作用于正在增长的最后消息和近视口 turn。
6. 刷新不应是恢复顺滑的唯一机制；如果页面原生状态本身需要刷新，诊断缓冲必须能显示扩展在事件附近的参与程度。
7. 既有 UNKNOWN 语义保持：拿不到可靠数据时不伪造 0 或百分比。

## Handoff acceptance

1. 一键生成结构化交接指令，但不自动发送。
2. 默认不读取完整聊天正文做本地抽取。
3. 交接模板显式区分 CURRENT / VERIFIED / PENDING / BLOCKED / HISTORICAL / REJECTED，避免旧版本复活或未验证事实升级。
4. 性能建议可以提示“准备换窗”，但最终换窗和发送由用户决定。

## Security / privacy

- 零网络请求、零遥测、零聊天正文持久化继续作为硬约束。
- 诊断记录仅内存、仅数值/状态，不含消息正文。
- 不新增远程服务、账号凭据或后台自动发送能力。
- Content Script 权限维持最小化；如新增 storage，仅保存用户明确的非敏感 UI 设置，不保存对话数据。

## Version / release policy

- 新版目标版本：`v1.7.0`。
- README、Manifest、安装说明、截图/功能描述统一只描述 v1.7 当前能力；v1.6.1 标为 obsolete/historical，不再作为推荐安装入口。
- Git 历史保留旧提交。旧 Release/Tag 是否删除属于高影响发布清理动作；在 v1.7 候选通过并形成新 Release 后再执行，避免先删除唯一可用包。

## Validation

- TDD：状态机、busy load shedding、ring buffer、交接模板、版本一致性先写失败测试。
- 兼容：PerformanceObserver/IntersectionObserver/MutationObserver 不可用时安全降级，UNKNOWN 语义不变。
- 静态：`node --check` + security tests。
- 行为：模拟 generating/scrolling/background，确认主动采样被抑制与恢复滞回。
- 真机：Edge/Chrome 长聊天中做“生成中滚动”和“持续使用后卡顿”A/B；v1.6.1 与 v1.7.0 比较扩展自耗时、卡顿事件、是否仍需刷新恢复。
